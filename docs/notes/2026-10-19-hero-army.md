# Hero army (2026-10-19)

Roadmap 4.3, first step. A hero carries up to seven creature stacks, each in its own slot, and the army is shown wherever Heroes 3 shows it on the adventure map. Only Skeletons for now, and creatures have no stats yet (5.1 is next).

## How Heroes 3 does it

- **Seven slots, by position.** A stack sits in a given slot and the others can be empty; the map editor places a hero's troops slot by slot.
- **A hero always has an army.** A hero with no creatures cannot exist on the map.
- **Exact counts for your own hero.** The info box and the right-click popup on your own hero show each stack's picture with the exact number in the corner. Monsters on the map, and other players' heroes, get size words ("Pack of") instead.
- **Status bar.** In the original game the adventure info box is a plain picture: hovering anywhere on it shows one fixed text for the whole box (`CInfoBar::hover`, `zelp[292]`), not one per slot. So the army slots add no status bar text.

## What we do

- A hero in the scenario has an `army`: up to seven slots in order, each `{ "creature": "SKELETON", "count": 12 }` or `null` for an empty slot. Creature types come from `game/data/monsters.json`.
- The loader does not check the army: every scenario is ours, and the demo scenario and the test builder (`aHero()`) always give the hero one. Checks belong with the scenario format work (milestone 9), when others write scenarios.
- `game/heroes/hero-army.js` turns the scenario army into the seven slots the hero box shows. The creature is named singular for a stack of one ("Skeleton") and plural otherwise, for screen readers and as the mouse tooltip.
- The hero box (`app/heroes/presentation/hero-box.js`) draws each stack as the creature's map look (no portraits yet) with the exact count in the bottom right corner, in the info box and in the hero's right-click popup.
- Nothing is stored in the event log: the army comes from the scenario and nothing changes it yet.
